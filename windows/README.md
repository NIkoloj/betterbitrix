# BetterBitrix Portable 0.3.3 — Windows x64

Пять значков в трее Windows: рабочий таймер, запуск/пауза, созвоны сегодня, дейлик и настройки. Окно появляется по нажатию. Приложение и веб-панель используют общий код календаря и таймера из `BetterBitrix.user.js`.

В 0.3.3 добавлено распознавание ссылок `teams.cloud.microsoft` в календаре и дейлике. Поддержка классических адресов Teams и Zoom, исправления повторов встреч и переноса длинных названий сохранены. В EXE включены .NET, ASP.NET Core и Windows Desktop Runtime 10.0.13.

[Скачать ZIP](https://github.com/NIkoloj/betterbitrix/releases/download/v2.3.3/BetterBitrixPortable-0.3.3-win-x64.zip) · [обновить мост](https://nikoloj.github.io/betterbitrix/windows/companion/BetterBitrixPortable.user.js).

## Первый запуск

1. Распакуйте **BetterBitrixPortable-0.3.3-win-x64.zip** в постоянную папку, доступную для записи, например `Документы/BetterBitrix`. Запустите **BetterBitrix.Desktop.exe**. Установщик, права администратора и отдельная установка .NET не нужны. Запускать прямо из ZIP не следует.
2. В открывшихся настройках нажмите **«1. Установить мост Tampermonkey»**. В браузере подтвердите установку **BetterBitrix Portable — мост**. Он устанавливается один раз рядом с обычным BetterBitrix; исходный скрипт оставьте включённым. Если локальная ссылка скачалась вместо открытия Tampermonkey, импортируйте `BetterBitrixPortable.user.js` из архива через панель Tampermonkey → «Утилиты» → импорт файла.
3. Нажмите **«2. Связать с браузером»**. Откроется Bitrix с одноразовым ключом. При запросе Tampermonkey разрешите этому мосту соединение с `127.0.0.1`. Используется текущая сессия Bitrix, дополнительного логина нет. Связь должна появиться через несколько секунд. Если корпоративный браузер запрещает запуск userscript или локальные соединения, это ограничение требует разрешения в его настройках/политиках.
4. Перетащите значки BetterBitrix из меню **«^»** к часам Windows, чтобы они оставались видимыми. В настройках приложения при желании включите **«Запускать при входе в Windows»**.

Для добавления моста и связывания используйте тот браузерный профиль, где уже установлены Tampermonkey и BetterBitrix и выполнен вход в Bitrix. Кнопки открывают браузер по умолчанию; при нескольких профилях можно скопировать открывшийся адрес в нужный профиль. После установки моста обновите уже открытые вкладки Bitrix.

Установщик и отдельное расширение браузера теперь не нужны. Сам по себе старый userscript не содержит протокола связи с Windows, поэтому один дополнительный мост необходим. Он берёт настройки, выбранную задачу и таймер из того же хранилища портала и использует тот же дневной журнал и Web Locks.

## Работа без браузера

- Запущенный таймер продолжает идти при закрытии вкладки, всего браузера и самого portable-приложения. Время вычисляется из сохранённой отметки начала; закрытие приложения не ставит день на паузу. Сохранённая пауза остаётся паузой.
- Последнее состояние, настройки и ссылки хранятся в **`data` рядом с EXE**. Переносите приложение вместе с этой папкой. Это личные рабочие данные; они не включаются в распространяемый архив.
- Дейлик и сохранённые ссылки сегодняшнего календаря можно открыть без Bitrix. Список помечается как сохранённый. Вчерашние события перестают отображаться после смены календарного дня, с учётом часового пояса Bitrix.
- Начало, пауза, продолжение и запись часов выполняются через сессию Bitrix: для них снова откройте Bitrix в браузере. Открывать дополнительные вкладки автоматически приложение не пытается. Если сессия истекла, войдите через обычную страницу Bitrix.
- Мост автоматически переподключается после перезапуска EXE/браузера. При нескольких вкладках выбирается одна; при её закрытии связь переходит к другой. Для «Текущей задачи» откройте карточку в связанной вкладке или оставьте нужную вкладку единственной.
- При обрыве связи во время записи часов нет автоматического повтора. Неподтверждённая отправка остаётся заблокированной даже после перезапуска EXE. Проверьте трудозатраты в задаче; затем используйте соответствующие кнопки подтверждения в настройках.

Время без связи отражает последнее известное состояние браузерного таймера. Если изменить его через другой браузер, portable-приложение увидит изменение после восстановления связи. Автономные паузы с последующим объединением изменений в этой версии не реализованы.

## Трей и автозапуск

| Значок | Нажатие |
| --- | --- |
| Часы сверху, минуты снизу | Открыть таймер и завершение дня |
| Запуск / пауза | Начать день, поставить на паузу или продолжить |
| Календарь с количеством | Созвоны сегодня |
| Камера | Дейлик |
| Шестерёнка | Настройки |

Полное время с секундами видно при наведении на таймер и в окне рабочего дня. Правый клик открывает меню с «Выходом». В настройках можно скрыть быстрые кнопки, оставив только таймер. Windows управляет видимостью и порядком значков; приложение восстанавливает их после перезапуска Explorer, без изменения панели задач и без плавающих накладок.

Автозапуск выключен по умолчанию. Единственное изменение системы по выбору пользователя — запись `BetterBitrixPortable` в `HKCU/Software/Microsoft/Windows/CurrentVersion/Run`. Отключение галочки удаляет её. Если переместили папку при включённом автозапуске, снова включите галочку из нового расположения. Перед удалением приложения отключите автозапуск, затем удалите папку и при желании мост из Tampermonkey. Данные оригинального скрипта на портале не удаляются.

## Настройка Bitrix

Если BetterBitrix уже настроен в этом профиле браузера, повторная настройка не нужна. Для первой настройки откройте карточку задачи, выберите её в настройках панели и нажмите «Настроить Bitrix». Затем сохраните через штатную форму 8 часов с комментарием `Работа над проектом`. Это настоящая запись за сегодня; следующий рабочий день запускайте после смены дня. Настройка и перехват запроса поддерживаются в фреймах того же портала.

## Обновление

Закройте приложение через трей и замените EXE новой portable-сборкой, сохранив папку `data`. Если изменился мост, установите новую версию `.user.js` и обновите вкладки. Автообновление EXE пока отсутствует. Сборка не подписана сертификатом издателя; Windows может показать проверку неизвестного приложения.

Исходники предыдущих итераций `Setup`, `NativeHost`, `extension` и технические install/uninstall-скрипты сохранены для истории. Они не входят в portable-архив и не используются при запуске 0.3.3. Если ранее вручную устанавливали 0.2, закройте её и отключите старое расширение, чтобы запускалась одна Windows-панель.

## Сборка и проверки

Для разработчика: Windows x64, актуальный .NET 10 SDK (релиз проверен на 10.0.402), Node.js, PowerShell 7. Пользователю они не требуются. Runtime сборки закреплён на 10.0.13 в `Directory.Build.props`.

```powershell
pwsh -File windows/scripts/build.ps1
pwsh -File windows/scripts/test.ps1 -SelfContained
pwsh -File windows/scripts/check-portable.ps1
```

Результат: `windows/dist/Portable/BetterBitrix.Desktop.exe` и `windows/.build/BetterBitrixPortable-0.3.3-win-x64.zip`. Архив содержит только EXE, мост и README. .NET включён в EXE; официальные runtime-пакеты берутся из NuGet. `-FrameworkDependent` у build.ps1 создаёт только разработческую сборку, требующую установленного .NET.

Тесты проверяют исходную браузерную функциональность, общий таймер и журнал, смену пользователя, календарь, транспорт Tampermonkey, передачу связи между вкладками, повторное подключение, одноразовое связывание, авторизацию локального HTTP, неопределённую запись, сохранение после закрытия браузера/перезапуска процесса, настоящий Windows Shell и состав portable-архива. Артефакты проверки — `windows/.build/smoke`. Тесты не обращаются к корпоративному Bitrix и не включают автозапуск. Работа моста в реальном профиле Tampermonkey и первая отправка в корпоративный Bitrix требуют проверки в живой сессии; локальные проверки не заменяют её.

## Устройство связи

```text
Значки Windows Shell ↔ portable EXE ↔ HTTP 127.0.0.1:47653
                       ↔ мост Tampermonkey ↔ текущая сессия Bitrix
```

Порт слушает только IPv4 loopback; публикации сервера в сеть нет. Связывание разрешается только после кнопки приложения, с одноразовым ключом на две минуты. Постоянный случайный ключ хранится в отдельном GM-хранилище моста; EXE сохраняет только его SHA-256. Cookies, пароль, sessid и профиль запросов Bitrix остаются в браузере. Проверяются связанный пользователь и ожидаемый пользователь каждой команды. Изменяющие команды доставляются один раз, их неопределённый результат сохраняется до проверки. Снимки записываются атомарно только при изменении рабочих данных; секундные тики таймера не переписывают диск.

API моста: [Tampermonkey @connect](https://www.tampermonkey.net/documentation.php?locale=en&q=connect), [Tampermonkey sandbox / unsafeWindow](https://www.tampermonkey.net/faq.php?ext=dhdg&q=Q404).

Мост использует `@sandbox raw`, как исходный BetterBitrix, чтобы оба скрипта работали в одном контексте страницы. Особенность режима описана в [документации Tampermonkey](https://www.tampermonkey.net/documentation.php?locale=en&q=sandbox). Для полного обновления 0.3.3 замените EXE и обновите мост. Связывание и GM-хранилище сохраняются при обновлении существующего скрипта; исходный BetterBitrix оставьте включённым. У моста теперь есть `@updateURL` и `@downloadURL`: последующие обновления проверяет Tampermonkey.

Генератор читает текущий `../BetterBitrix.user.js`, добавляет адаптер и транспорт, не монтируя дополнительную панель в DOM. Замороженный `upstream/BetterBitrix-2.3.1.user.js` сохранён для истории. Исправления общего кода автоматически попадают в Windows-мост при сборке.
